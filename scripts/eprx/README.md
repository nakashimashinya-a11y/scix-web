# EPRX 取引結果CSVの集計（コラム50）

`aggregate_column50.py` は、EPRX（電力需給調整力取引所）の取引結果CSVから、一次調整力（`1-0`）・一次オフライン（`1-1`）・複合商品（`4-0`）の価格と、応札・落札の比率を、9管区＋全国・期間別に集計する。電源種別別（全国・速報値）も同じ期間で集計する。標準ライブラリだけで、python3.9 でも動く。

## 使い方

```sh
python3 scripts/eprx/aggregate_column50.py                          # 既定のデータ根と出力先
python3 scripts/eprx/aggregate_column50.py <データ根> <出力先> --end 2026-09-29
python3 scripts/eprx/aggregate_column50.py --check                  # 1コマの検算（下の「検算」）
```

- 既定のデータ根は `~/マイドライブ/9_システム/外部資料/EPRX`、出力先は `docs/research/column-50/`。
- データ根の下を探して、`速報値/{YYYYMM}_{商品}_prompt.csv`・`確報値/{YYYYMM}_{商品}_result.csv`・`電源種別別/{YYYYMM}_{商品}_rt_prompt.csv`（商品は 1-0・1-1・4-0、2026年4月分から）を拾う。あとから置いたファイル（9月の確報値、1-1 の電源種別別など）は、次の実行で自動で入る。同じ名前のファイルが2か所にあると止まる。
- `--end`（既定 2026-09-29）は P2 の最後の受渡日。これより後の受渡日は集計に入れない。1-1 の速報値は 9/30 と10月分まであるが、1-0・4-0 の速報値が 9/29 受渡分までなので、3商品そろえて 9/29 で切っている。
- CSV の形が想定と違う（列や項目が無い、数値でない値がある、最後に E 行が無い、ブロック数が48でない など）ときは、黙って進めずに止める。
- ダウンロードはしない。手で取った CSV を読むだけ。

## 出典・取得日・規約

- 出典: EPRX「取引結果」 https://www.eprx.or.jp/information/results.php （免責事項に同意すると一覧が開く）
- 取得日:
  - 2026-09-29: 1-0・4-0 の速報値 4〜9月（9月は29日受渡分まで）・確報値 4〜7月・電源種別別 4〜9月
  - 2026-10-04: 1-1 の速報値 4〜10月（9/30 と 10/1〜10/4 を含む）・確報値 4〜8月、1-0・4-0 の確報値 8月（同じ日に取り直した 1-0・4-0 の確報値 4〜7月は、手元の分と md5 が一致）
- 規約: 公開データを商用目的（個人・組織内の利用を除く）で使うときは、事前に EPRX との契約が要る。自動的な大量取得（スクレイピング等）は、EPRX の事前承諾が要る。取るのは要る分だけ、手で1本ずつ。

## CSV の形（実ファイルで確かめた）

- 文字コード CP932・改行 CRLF。1行目 `H`、2行目 `P`（速報値/確報値・対象年月・商品区分・ブロック数48）、3行目 `TT`（列名）、最後の行が `E`。
- キーは `YYYYMMDDBnn`（受渡日＋30分コマ B01〜B48）。
- 速報値の列: `取引情報, 北海道, 東北, 東京, 中部, 北陸, 関西, 中国, 四国, 九州, 合計`。1コマ13行。
- 確報値の列: `調達区分, 取引情報, 北海道 … 九州, 合計`。調達区分は `システム約定結果`・`追加調達結果`・`合計（確報値）` の3つで、1コマ39行。使うのは `合計（確報値）` の行だけ。
- 電源種別別の列: `取引情報, 火力発電, 水力・揚水発電, 蓄電池, VPP, 合計`（全国だけ・速報値だけ）。1コマ5行。
- P 行の商品区分: 1-0 は `一次調整力`、1-1 は `一次オフライン`、4-0 は `複合商品`。
- 価格の単位は 円/kW・30分（税抜）。電源属地別＝電源のあるエリア、TSO別＝調達する送配電のエリア。

使う項目名（CSV の原文）:

| 欄 | 速報値 | 確報値（`合計（確報値）` の行） |
|---|---|---|
| 募集量 | `募集量（TSO別）[MW]` | 同じ |
| 応札量 | `応札量合計（電源属地別）[MW]` | 同じ |
| 落札量 | `落札量合計（電源属地別）[MW]` | `約定量合計（電源属地別）[MW]` |
| 平均価格 | `平均落札価格（電源属地別）[円/kW・30分]` | `平均約定価格（電源属地別）[円/kW・30分]` |
| 最高価格 | `最高落札価格（電源属地別）[円/kW・30分]` | `最高約定価格（電源属地別）[円/kW・30分]` |
| 落札量（TSO別） | `落札量合計（TSO別）[MW]` | `約定量合計（TSO別）[MW]` |
| 平均価格（TSO別） | `平均落札価格（TSO別）[円/kW・30分]` | `平均約定価格（TSO別）[円/kW・30分]` |

電源種別別で使う項目名: `落札量合計[MW]`・`平均落札価格[円/kW・30分]`・`最高落札価格[円/kW・30分]`（ほかに `落札件数[件]`・`最低落札価格[円/kW・30分]` がある）。

`外部資料/EPRX/README.md` の書き方と違う点（実ファイルを正とした）:

- 確報値の `合計（確報値）` と `追加調達結果` の行は「落札」でなく「約定」の語（`システム約定結果` の行は「落札」）。
- 電源種別別の列名は `火力発電`・`水力・揚水発電`（README の「火力・水力揚水」は略記）。
- `合計（確報値）` は `システム約定結果` と `追加調達結果` の単純な和ではない。1-0 の 2026年4〜8月では追加調達がすべて0なのに、落札量で約11%・応札量で約13%のセルが `システム約定結果` と違う。速報値と確報値の差はこの修正から来る。

「-」は、2026年4〜9月の 1-0・1-1・4-0 では `追加調達結果` の `募集量（TSO別）` にだけあり（使わない行）、集計に使う行には無かった。出たときは数値なしとして扱い、そのコマを除外コマとして数える。

## 期間と上限価格

- P1 = 2026-04-01〜2026-08-31、P2 = 2026-09-01〜`--end`。
- ΔkW 上限価格（一次・一次オフライン・複合）は、P1 が 15.00円/ΔkW・30分、P2（2026/9/1 受渡分から）が 10.00円/ΔkW・30分。需給調整市場システムは上限を超える札も約定させ、精算の段階で上限に切り下げる（EPRX「需給調整市場のΔkW上限価格について」2026/7/30 更新。当社 COLUMN 41 `column-price-cap.html` に要約）。
- そのため CSV の最高落札価格には、上限を超える表示値がある（P1 は15円超、P2 は10円超）。このスクリプトの数（≧10円・上限超）と加重平均は表示値のまま計算していて、精算後の値ではない。

## 式（1コマ＝30分。管区＝その列、全国＝CSV の「合計」列）

1. 加重平均 ＝ Σ(平均落札価格[電源属地別] × 落札量[電源属地別]) ÷ Σ落札量[電源属地別]。落札量が0か「-」のコマと、平均価格が「-」のコマは除き、除外コマ数を出す（落札量0のコマは重み0なので、除いても値は変わらない）。
2. 最高 ＝ 最高落札価格[電源属地別] の期間内最大値。最高日＝それが最初に出た受渡日。同じ値が出た日数とコマ数も出す。
3. ≧10コマ数 ＝ 最高落札価格[電源属地別] ≧ 10 のコマ数。≧10日数 ＝ そのコマが1つでもある受渡日の数。上限超コマ数・日数は、同じ数え方で「最高落札価格 ＞ その期間の上限」。
4. 応札/募集 ＝ Σ応札量[電源属地別] ÷ Σ募集量[TSO別]。分子は電源のあるエリア、分母は調達する送配電のエリアで、基準が違う。管区の値はエリアをまたぐ応札・調達を含むので、その管区の需給の締まり具合そのものではない（全国は同じ基準になる）。
5. 落札/応札 ＝ Σ落札量[電源属地別] ÷ Σ応札量[電源属地別]。
6. 参考_TSO別加重平均 ＝ Σ(平均落札価格[TSO別] × 落札量[TSO別]) ÷ Σ落札量[TSO別]（落札量[TSO別] が0のコマを除く）。
7. 電源種別別: 加重平均 ＝ Σ(平均落札価格 × 落札量合計) ÷ Σ落札量合計（落札量合計が0のコマを除く）。最高・≧10・上限超は上と同じ数え方。Σ落札量＝落札量合計の和。落札量シェア ＝ その種別の Σ落札量合計 ÷ 「合計」列の Σ落札量合計。

- 速報と確報は別々に出す（混ぜない）。
- 全国の加重平均は「合計」列の平均価格（小数2桁の表示値）で計算する。9管区の積み上げとの差は、実行するたびに表示する。
- Σ の列は MW×コマ の和（そのまま足しただけで、kWh や金額ではない）。

## 出力（`docs/research/column-50/`）

- `eprx_summary.csv`（UTF-8・BOM付き・縦長・数値は丸めない）: 区分（速報/確報）×商品×期間×管区（9管区＋全国）の120行。
  - 列: 区分, 商品, 商品名, 期間, 期間の範囲, 管区, 加重平均, 最高, 最高日, ≧10コマ数, ≧10日数, 応札/募集, 落札/応札, 参考_TSO別加重平均, 対象コマ数（期間内の全コマ）, 除外コマ数（加重平均から除いたコマ）, 最初の受渡日, 最後の受渡日, 最高の出た日数, 最高の出たコマ数, 上限, 上限超コマ数, 上限超日数, TSO別_除外コマ数, 応札/募集_除外コマ数, 落札/応札_除外コマ数（「-」で除いたコマ）, 欠けている日, Σ募集量, Σ応札量, Σ落札量, Σ落札量TSO別, 元ファイル一覧
  - データが無い組（確報の P2 など）も行は残し、値を空にして、対象コマ数 0・欠けている日「（データ無し）」とする。
- `eprx_by_type.csv`（同じ形式）: 商品×期間×電源種別（速報値・全国）。
  - 列: 区分, 商品, 商品名, 期間, 期間の範囲, 電源種別, 加重平均, 最高, 最高日, ≧10コマ数, ≧10日数, Σ落札量, 落札量シェア, 対象コマ数, 除外コマ数, 最初の受渡日, 最後の受渡日, 最高の出た日数, 最高の出たコマ数, 上限, 上限超コマ数, 上限超日数, 欠けている日, 元ファイル一覧
  - 電源種別別のファイルが1本も無い商品（いまは 1-1）は行を作らず、md に注記する。
- `eprx_summary.md`: 表示用に丸めた表（管区×期間の表と、最後に電源種別別の表）。

## 検算

- `--check` は、研究で読んだ 2026/9/1 B01・1-0 速報の1コマ（東北 最高15・平均6.91・応札79.309・募集175、東京 最高10・平均4.04、四国 平均0.64・応札214.473・募集41、合計 落札1459.181・平均3.53）を、集計と同じ読み取り関数で読み直して照合する。
- 通常の実行でも、電源種別別の「合計」列と本表の速報・全国（Σ落札量・加重平均・≧10コマ数）が一致するかを表示する。
